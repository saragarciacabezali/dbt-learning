# dbt Review Answers

This file contains polished answers based on your responses from the review session.

## Part 1: Core concepts

1. What is dbt?
   dbt is a tool used to transform data in a warehouse using SQL, and to organize that work into a structured project with models, tests, and documentation.

2. What is a dbt model?
   A dbt model is a SQL file that defines a transformation and, when run, is compiled into SQL and materialized as a table, view, or other object in the warehouse.

3. What is the purpose of dbt_project.yml?
   dbt_project.yml defines the project configuration, including the project name, dbt version, model paths, default materializations, and references to the project setup.

4. What is the purpose of profiles.yml?
   profiles.yml stores the connection details for the warehouse, such as the project or database, dataset, and authentication information needed for dbt to connect.

5. What is the difference between a model and a source?
   A model is a transformation created by dbt, while a source is an upstream dataset or table that the model reads from as raw input.

6. What does dbt run do?
   dbt run compiles the selected models, runs them in dependency order, and creates or updates the corresponding objects in the warehouse.

7. What does dbt test do?
   dbt test runs the tests defined for models and sources to validate data quality and reports which checks passed or failed.

8. What does dbt debug do?
   dbt debug checks whether the dbt environment and project are configured correctly and whether dbt can connect to the warehouse.

9. What is the target directory used for?
   The target directory stores dbt runtime artifacts such as compiled SQL, run results, manifests, lineage graphs, and partial parse metadata.

10. What is lineage in dbt?
    Lineage is the dependency graph that shows how models and sources relate to each other and how data flows through the project.

## Part 2: Project understanding

11. In this project, what does the models folder contain?
    At the moment, it contains a simple starting model in the staging layer to verify that the dbt project and database setup are working correctly.

12. In this project, what is the role of the staging folder?
    Right now, the staging folder is mainly a basic example area, but in general it is used for initial cleaning and standardization of data before it moves to later layers.

13. What is the purpose of the Makefile in this repo?
    The Makefile improves the user experience by providing shortcuts such as an alias that helps users enter the project directory and activate the environment more easily.

14. What does the target folder usually contain after a run?
    It usually contains compiled SQL, run artifacts, a manifest, a lineage graph, and other metadata generated by dbt.

15. What is the purpose of the compiled and run subfolders under target?
    These folders store the generated SQL for each model in its compiled and executed form so you can inspect exactly what dbt produced and ran.

## Part 3: Review and reflection

16. Why are dependencies important in a dbt project?
    Dependencies are important because dbt needs to know the correct order to run models so upstream data is available before downstream transformations.

17. Why is testing important in dbt?
    Testing is important because it helps check data quality and build trust in the data and the transformations used by the project.

18. Why might documentation be useful in a dbt project?
    Documentation helps explain the logic, purpose, and structure of models and the broader project so others can understand and maintain it more easily.

19. What is the difference between understanding a concept and being able to use it confidently?
    Understanding a concept means you can explain it, while using it confidently means you can apply it yourself in real situations without much help.

20. If a model fails, what are the first things you would check?
    I would inspect the generated SQL in the target folder, especially the compiled and run artifacts, and then check for syntax or reference issues in the model.
